# Виртуальный скрининг ингибиторов DYRK1A

Пайплайн поиска низкомолекулярных ингибиторов киназы **DYRK1A** — мишени для терапии
болезни Альцгеймера. От выбора мишени и сбора данных ChEMBL до генерации молекул,
молекулярного докинга и отбора кандидатов по 13 критериям.

Решение команды «Квадрицепс», хакатон DataCon 2025.

## Главный результат

**Ни одна из 814 молекул не проходит все 13 строгих критериев, предъявляемых
к препарату для ЦНС.** Лучшие кандидаты проходят 10 из 13.

Это отрицательный результат, и он основной. Три барьера, на которых останавливаются
даже лучшие молекулы:

| Барьер | Проходит | Почему важно |
|--------|---------:|--------------|
| P-gp efflux < 2 | 46 из 814 (5.7 %) | белок-насос выбрасывает молекулу обратно через гематоэнцефалический барьер |
| Docking score < −8 ккал/моль | 38 из 814 (4.7 %) | недостаточная предсказанная аффинность к DYRK1A |
| hERG < 0.3 | 32 из 814 (3.9 %) | риск кардиотоксичности |

Генератор уверенно выдаёт молекулы, похожие на лекарства по общим правилам
(89.3 % проходят Lipinski), но целевая аффинность и профиль безопасности
остаются узким местом — именно туда имеет смысл направлять следующую итерацию.

## Выбор мишени

Из шести кандидатов, обсуждаемых в контексте болезни Альцгеймера — Aβ, тау-белок,
TREM2, GSK-3β, DYRK1A, Fyn — выбрана **DYRK1A**. Критерии отбора и разбор каждого
кандидата: [research.md](research.md).

Коротко, почему DYRK1A:

- участвует в патогенезе через фосфорилирование тау-белка и образование Aβ;
- десятки ингибиторов с измеренной активностью в нМ диапазоне (гармин, IC₅₀ ≈ 80 нМ;
  SM07883, IC₅₀ = 1.6 нМ) — достаточно данных, чтобы обучить QSAR-модель;
- решены кристаллоструктуры с лигандами (PDB 4YU2, 6T6A, 6S14) — есть куда докировать;
- отчётливый ATP-связывающий карман: ингибиторы DYRK1A уже находили in silico;
- экспрессия уже, чем у GSK-3β, — потенциально лучший профиль безопасности, а SM07883
  снизил тау-патологию и нейровоспаление в моделях БА при пероральном введении.

## QSAR-модель активности

Данные: ChEMBL, мишень `CHEMBL2292`, значения IC₅₀.

- **Дескрипторы**: Mordred, PaDEL и RDKit, затем отбор наиболее информативных признаков.
- **Валидация**: *scaffold split*, а не случайное разбиение. Это принципиально:
  случайный split завышает метрики, потому что близкие аналоги попадают
  и в обучение, и в тест. Scaffold split разводит химические серии и показывает,
  как модель работает на действительно новых каркасах.
- **Модель**: XGBoost с GPU-ускорением, гиперпараметры подобраны Optuna.

Результат: **R² = 0.628, RMSE = 0.718** на scaffold split.

## Генерация молекул

Основная часть работы — перебор подходов. Из шести опробованных пять отвергнуты,
и это задокументировано: что именно не сработало, тоже результат.

| Подход | Статус | Почему |
|--------|--------|--------|
| SELFIES VAE | отвергнут | низкая валидность генерируемых структур |
| Transformer VAE | отвергнут | то же; обучение нестабильно |
| DPO (Direct Preference Optimization) | отвергнут | сложность настройки, нестабильность |
| RLHF | отвергнут | то же; остался в репозитории как прототип |
| Docking-guided generation | отвергнут | технические сложности интеграции докинга в цикл генерации |
| **Fine-tuning `entropy/gpt2_zinc_87m`** | **выбран** | стабильное обучение, высокая валидность |

Финальный вариант — дообучение предобученной модели на 3 эпохи.
Loss: 2.71 → 0.66 → 0.32. Дальше не обучали, чтобы не переобучиться.
Валидность: **981 молекула из 1000**.

> Код отвергнутых подходов оставлен в `step_03_molecule_generation/` намеренно —
> как след проделанной работы. Эти модули не участвуют в финальном пайплайне,
> часть из них — незавершённые прототипы (в `rlhf_finetuner.py` цикл PPO
> не реализован, стоит заглушка).

## Виртуальный скрининг

- Подготовка белка: очистка структуры DYRK1A, удаление лишних цепей и растворителя.
- Подготовка лигандов: конвертация в PDBQT, генерация 3D-конформеров.
- Докинг: AutoDock Vina с GPU-ускорением.
- Ранжирование: композитный скор по docking score, ADMET-свойствам,
  CNS-специфичным параметрам и лигандной эффективности (LE, LLE).

До докинга дошли 814 молекул, успешно отдокированы **809**, для 5 не удалось
подготовить корректную 3D-структуру.

До докинга дошли 814 молекул из 981 валидной. Чем именно отфильтрованы
остальные 167, по коду и артефактам репозитория однозначно не восстанавливается —
этот шаг не был зафиксирован, и честнее это признать, чем задним числом
придумывать объяснение.

## Установка и запуск

Нужны Python 3.11+, [uv](https://github.com/astral-sh/uv), OpenBabel и AutoDock Vina.

```bash
# OpenBabel и AutoDock Vina
sudo apt-get install openbabel autodock-vina    # Debian/Ubuntu
brew install open-babel autodock-vina           # macOS
sudo pacman -S openbabel autodock-vina          # Arch

git clone https://github.com/gulldan/datacon2025hack.git
cd datacon2025hack
uv sync
```

Запуск пайплайна целиком:

```bash
./run.sh
```

Отдельные стадии:

```bash
uv run python step_01_target_selection/run_target_analysis.py
uv run python step_02_activity_prediction/run_prediction_model.py
uv run python step_03_molecule_generation/run_generation.py
uv run python step_04_hit_selection/run_hit_selection.py
```

Параметры — пути, бокс докинга, пороги фильтров — собраны в `config.py`.

## Воспроизводимость

```bash
uv run pytest tests/ -q
```

29 проверок пересчитывают счётчики из раздела «Результаты» прямо из таблиц
с дескрипторами. Если прогон пайплайна изменит числа, тест упадёт, и README
придётся обновить тем же коммитом.

Докинг-конформеры лигандов (`*.pdbqt`) и матрицы дескрипторов не хранятся в git —
они пересоздаются стадиями 2 и 4. Подготовленный рецептор
`step_04_hit_selection/docking/3ANQ_receptor.pdbqt` оставлен в репозитории:
без него докинг не воспроизвести.
